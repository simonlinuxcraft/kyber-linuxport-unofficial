# Release artifacts and how each one is built

Three artifacts ship per release. They all come from the same Flutter build, so
build once and derive the rest, in the order below.

| Artifact | For | Needs FUSE | Self-update |
|---|---|---|---|
| `KyberLinuxPort-x86_64.AppImage` | the default case | yes | on |
| `KyberLinuxPort-x86_64.tar.gz` | Steam Deck, systems where the AppImage fails | no | off |
| `PKGBUILD` | Arch, CachyOS | no | off |

## Prerequisites

Flutter (master channel), Rust stable, GTK 3 dev packages, patchelf, librsvg
tooling. The tested SDK revision is recorded in `tools/flutter-revision`;
`tools/build-appimage.sh` warns when the local checkout differs. Match it with:

```bash
git -C "$(dirname "$(dirname "$(readlink -f "$(command -v flutter)")")")" checkout "$(cat tools/flutter-revision)"
```

The renderer is not a build-time choice. The runner picks it at startup from
`KYBER_RENDERER`, then `~/.config/kyber-linuxport/renderer`, then the compile
default in `Kyber/Launcher/linux/my_application.cc` (`KYBER_DEFAULT_SKIA`,
currently `FALSE`, meaning the engine default Impeller).

## 1. Flutter bundle

```bash
cd Kyber/Launcher && flutter build linux --release
```

Output: `Kyber/Launcher/build/linux/x64/release/bundle/`. Everything below
depends on this, so rebuild it after any code change.

## 2. AppImage

```bash
tools/build-appimage.sh
```

Populates `tools/KyberLinuxPort.AppDir` from the bundle (the AppDir is wiped and
regenerated every run), lets linuxdeploy pull in the GTK stack, patches AppRun
with the `KYBER_*` hook blocks, fixes RUNPATHs, and packs the result.

Output: `tools/KyberLinuxPort-x86_64.AppImage` plus `tools/latest.json`.

Any change to AppRun or to a hook must go into `tools/build-appimage.sh` as a
sentinel-guarded patch block. Editing the AppDir by hand is pointless, the next
build deletes it.

## 3. Tarball

Run after the AppImage, it reuses the AppDir that step 2 produced.

```bash
cd tools && tar --transform 's,^KyberLinuxPort\.AppDir,KyberLinuxPort,' -czf KyberLinuxPort-x86_64.tar.gz KyberLinuxPort.AppDir
```

Output: `tools/KyberLinuxPort-x86_64.tar.gz`, around 183 MB, roughly 15 seconds.
`--transform` renames the top-level directory so users unpack `KyberLinuxPort/`
rather than something ending in `.AppDir`.

Users unpack it anywhere and run `./AppRun`. Two AppRun hooks disable themselves
in that situation, which is what makes the tarball safe to ship:

- the self-install hook returns early when `$APPIMAGE` is unset
  (`tools/kyber-self-install.sh:26`)
- the container self-updater needs an `appImagePath`, which comes from the same
  variable (`lib/core/services/appimage_update_service.dart:80`)

Neither needs a flag from us. Verify after building by unpacking to a scratch
directory, running `./AppRun` without any environment, and confirming that
`~/Applications` is untouched afterwards.

## 4. PKGBUILD

`packaging/linuxport-bin/PKGBUILD` pulls the tarball from the release, not the
AppImage, so the package has no FUSE dependency. It installs to
`/opt/kyber-linuxport-bin`, adds a `/usr/bin/kyber-linuxport` wrapper, the menu
entry, all ten icon sizes and the qrc and nxm/kl scheme handlers.

Per release, three fields need updating:

- `_appver` and `pkgver` (pkgver uses underscores, hyphens are not allowed)
- `sha256sums`, from `sha256sum tools/KyberLinuxPort-x86_64.tar.gz`

The checksum ties the PKGBUILD to one specific tarball. Upload both assets
together; replacing the tarball alone makes `makepkg` fail on a checksum
mismatch.

The wrapper sets `KYBER_NO_AUTO_INSTALL=1` and an explicitly empty
`KYBER_UPDATE_URL`. AppRun tests that one with `${VAR+x}`, so an empty value
still counts as set and keeps the self-updater off. pacman owns that copy and is
the only thing allowed to replace it. `KYBER_NO_AUTO_INSTALL=1` also stops the
launcher from registering its own nxm/kl handler on every start, so the packaged
`kyber-linuxport-nxm.desktop` stays the default.

This is separate from `packaging/aur/PKGBUILD`, which mirrors the AUR package
`kyber-launcher-unofficial-appimage`. Despite its name that one now builds
Yilmaz4's native tarball and is unrelated to the AppImage.

## Publishing

All three go to the same release as assets. On a re-upload the tarball and the
PKGBUILD must move together, see the checksum note above. `latest.json` drives
the in-app updater and is regenerated by `tools/build-appimage.sh`, so upload
the one from the same run.

## Verification before publishing

1. Start the AppImage and confirm it reaches the first UI frame.
2. Check the renderer line in the terminal: `Renderer: impeller` by default,
   `Renderer: skia` with `KYBER_RENDERER=skia`, and the Impeller backend line
   must disappear in the second case.
3. Unpack the tarball and start `./AppRun` with no environment set, then
   confirm `~/Applications` is unchanged.
4. Build the PKGBUILD with `makepkg -si` on an Arch or CachyOS machine, then
   start it from the application menu. This step cannot be done on the Ubuntu
   build host.
